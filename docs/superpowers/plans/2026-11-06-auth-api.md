# Autentikasi API (Register & Login) Sesuai Skema SAKSI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Membangun dan menyesuaikan API autentikasi (`POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `GET /api/v1/auth/me`) dengan skema database PostgreSQL `SAKSI.sql`, di mana registrasi dibatasi secara ketat hanya untuk role perangkat desa (`kades`), penyedia (`penyedia`), dan warga (`warga`).

**Architecture:** Menerapkan Clean Architecture (Hexagonal) pada backend Go: Domain entities -> Use Case / Ports -> Adapter HTTP & PostgreSQL. Pendaftaran user menggunakan transaksi database atomik yang mengisi tabel `users`, tabel relasi `user_roles`, serta tabel profil spesifik (`warga_profiles` atau `counterparties`).

**Tech Stack:** Go 1.22+, PostgreSQL 16, pgx/v5 (pgxpool), golang.org/x/crypto/bcrypt, crypto/hmac (SHA-256 token).

**Spec:** [`docs/PRD.md`](file:///d:/Farrel/PROJECTS/SAKSI/docs/PRD.md) dan [`backend/scripts/SAKSI.sql`](file:///d:/Farrel/PROJECTS/SAKSI/backend/scripts/SAKSI.sql).

## Global Constraints

- Skema database mengikuti tabel di [`backend/scripts/SAKSI.sql`](file:///d:/Farrel/PROJECTS/SAKSI/backend/scripts/SAKSI.sql) (`users`, `user_roles`, `warga_profiles`, `counterparties`, `villages`).
- Tipe `users.id` adalah `BIGINT` (Go: `int64`), bukan `string` UUID.
- Registrasi mandiri hanya diizinkan untuk 3 peran: `kades` (Perangkat Desa), `penyedia`, dan `warga`. Peran pengawas (`bpd`, `inspektorat`, `admin_daerah`) ditolak saat register publik.
- Token autentikasi berbasis HMAC SHA-256 statis terenkode Base64URL yang menyimpan `uid` (int64), `role`, `villageId`, dan `exp`.
- Semua operasi register yang melibatkan multi-tabel (`users` + `user_roles` + profil) wajib dijalankan di dalam satu database transaction (`pgx.Tx`).

## Review Focus

1. **Role Restriction Enforcement:** Input role di luar `kades`/`perangkat_desa`, `penyedia`, dan `warga` harus ditolak dengan HTTP 400 Bad Request.
2. **Atomic Rollback on Failure:** Jika insert ke `user_roles` atau `warga_profiles`/`counterparties` gagal, data user di tabel `users` tidak boleh tertinggal (rollback bersih).
3. **Foreign Key Validation:** Registrasi perangkat desa atau warga dengan `village_id` yang tidak ada di tabel `villages` harus mengembalikan HTTP 400 / 404 informatif, bukan unhandled database panic.
4. **Duplicate Email Conflict:** Registrasi dengan email yang sudah ada harus mengembalikan HTTP 409 Conflict.
5. **Password Security:** Password di bawah 8 karakter ditolak, password disimpan dalam format hash bcrypt cost 10.
